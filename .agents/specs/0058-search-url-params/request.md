에너지 데이터들은 15분동안 유지하고 15분 지나면 지우고 그리고 다른 정적 데이터들은 도메인 규칙에 따라서 시간을 정한다거나 통계데이터나 이런거 검색은 내가 문서대로 했던거 같은데 설비 검색할때 그리고 정적데이터가 변경되는 시점이 중요한데 이거는 백엔드 웹훅을 사용했어 1번의 사용자가 1번을 수정하고 이후에 2번의 사용자가 만약 재조회를 안하면 새로온 데이터를 모르잖아 1번 과 2번의 사용자가 1번을 수정하지 않은 상태애서 조회를 하면 2번의 사용자는 조회를 하기전까지는 무효롸처리를 안하잖아 그래서 정합성 을 지키기 위해서 웹훅을 사용했고 데이터가 변경되면 넥스트 서버쪽으로 푸쉬를 해 그러면 프론트에서는 사용자한테 제공을해 2번의 사용자가 1번의 사용자의 데이터를 수정하려고 한다면 백엔드가 푸쉬를 했으니까 백엔드가 1번의 사용자가 어디 필드가 수정이 되었다 몇시에 누가 했다 이런걸 알려줘 그러면 2번의 사용자가 그걸 확인하고 덮어쓸지 아니면 취소 버튼 누르면 재조회 하면서 데이터를 최신회 시키고 그렇게 했어 필요할대 직접도 했고 이것도 했고 오케잉? 무슨말이지 알아??
